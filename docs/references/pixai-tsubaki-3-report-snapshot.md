## PixAI 报告说了什么

### 1. 目标和数据规模

Tsubaki.3 面向动漫领域，同时训练 text-to-image 和 in-context generation。动漫数据整理从约 5 亿个 image-text pair 开始，经过整理后约保留 5000 万个 pair。报告把主要问题归为四类：质量过滤、去重、caption 统一和概念平衡。

### 2. 先训练动漫专用的视觉表征

报告指出，通用 SigLIP 2 的聚类容易按主体、构图和语义聚在一起，风格差异很大的图片可能仍落入同一簇。为此，PixAI 在去重后的公开动漫数据上微调 SigLIP 2 SO400M，得到 `SigLip-Anime`。过滤分类器和后续概念聚类都复用这个表征空间。

这意味着 Tsubaki.3 的“簇”不是单纯接受通用 embedding 的结果，而是先针对动漫领域调整过的视觉空间。

### 3. 过滤

过滤分为由便宜到昂贵的阶段：

- 元数据检查：损坏/近空文件、分辨率或像素数不足、极端宽高比、方向标记不一致；
- 图像启发式检查：过曝、过饱和、马赛克、模糊；
- 五类轻量分类器：水印、低美学、广告样式、真人、AI 生成图。

分类器使用小型人工 gold set，并用 VLM 任务提示扩展伪标签。大多数过滤器输出连续分数；从预训练到 SFT 逐步收紧阈值，早期保留覆盖，后期更重质量。

### 4. 去重

PixAI 使用 SSCD copy-detection descriptor，再用 FAISS 做近邻搜索，既做数据集内去重，也做跨数据集去重。报告给出明确阈值：通常余弦相似度大于 `0.9` 的图像归为重复组并保留一个代表；对合法变体使用 `0.92–0.98` 的更高阈值；超过 `0.995` 的配对始终合并。代表图按来源可靠性优先、图像质量其次选择。

### 5. Caption 和 tag

保留图片会由 Qwen3.5-27B 和 Tagger 1.0 重新生成两类文本：

- tag list：主要对象和属性；
- 自然语言 caption：风格、光照、氛围和细节，分短/中/长三种长度。

文本丰富的图片还会被要求转录可见文字。报告中的 Tagger 1.0 是一个独立的动漫标签模型，预测 30,877 个 tag；它不是 e621 的原始 tag 数据本身。

### 6. 概念平衡和长尾

过滤、去重后，数据仍会被“居中的单角色肖像”主导，稀有风格、物体和属性不足。PixAI 的做法是：

1. 为长尾概念收集定向补充数据；
2. 对补充数据过采样；
3. 对其余数据做 concept-aware re-weighting；
4. 用 `SigLip-Anime` embedding 的层次聚类得到概念分区；
5. 采样簇以保留长尾风格，同时不把训练预算浪费在头部概念；
6. 小簇不自动等于有价值：只有成员视觉上连贯的小簇才上调，边框、水印、采集重复等小簇会被封顶。

报告还展示了 style proper noun 检索在约 60% 附近提前平台化，以此动机支持长尾概念增加训练曝光；这说明长尾采样是为了提高学习机会，不是单纯追求标签数量均衡。

## 与 Krea 2 官方报告的关键区别

对照来源：[Krea 2 Technical Report](https://www.krea.ai/blog/krea-2-technical-report)，本地摘录见上方缓存文件。

| 维度 | Tsubaki.3 | Krea 2 |
|---|---|---|
| 主要目标 | 动漫领域的风格、角色、属性和概念覆盖 | 通用图像生成基础模型的广域世界知识与风格覆盖 |
| 数据范围 | 约 5 亿动漫 image-text pair → 约 5000 万 | 报告描述的是大规模通用预训练与 midtraining；不以动漫单域为中心 |
| 聚类表征 | 先把通用 SigLIP 2 微调为 `SigLip-Anime`，再用于过滤和概念聚类 | 报告描述 FAISS hierarchical k-means 和语义聚类，但没有给出同等的动漫专用 embedding 方案 |
| 长尾策略 | 定向补充数据 + 过采样 + 其余数据重加权；小簇先检查视觉连贯性 | 对层次簇采样，保留 long-tail visual concepts，避免头部概念过采样 |
| VLM 的簇作用 | 报告明确写 VLM 用于过滤器伪标签；概念平衡段没有写 K2 式“查看质心邻近样本并命名/标记簇”流程 | 明确让 VLM 查看每个簇质心附近图像，命名/标记簇；人工审核 flagged clusters 后移除问题簇 |
| 去重 | SSCD + FAISS，报告给出 `0.9`、`0.92–0.98`、`0.995` 阈值和代表选择规则 | 低分辨率阶段主要用 md5/phash/colorhash；midtraining 剩余叶簇内用 SigLIP 相似度做语义去重 |
| Caption | 对保留图全部重 caption，tag list 和自然语言 caption 并行 | 多阶段 caption pipeline，使用 OCR、已有元数据和富文本 caption；报告还用 caption 做概念覆盖检索 |
| 概念词典 | 动漫 tagger 和动漫领域概念，报告强调动漫社区的 tag 体系 | Wikipedia PageRank + Wikidata 过滤，再在 caption 中覆盖约 500 万概念 |
| 覆盖风险 | 重点是动漫风格/角色/属性长尾被头部肖像淹没 | 重点是通用世界知识实体在语义采样中被完全丢失 |
| SAE | 这段动漫数据整理流程没有对应 K2 式 SAE 伪影标签步骤 | K2 预训练部分另有 SigLIP-2 SAE + VLM 特征注释，用于无监督伪影/特征筛选 |

## 对你的 e621 LoRA 项目的含义

### 应该优先借鉴什么

你的数据形态更接近 Tsubaki.3 的动漫/booru 场景，但你要求以 K2 为主，因此可以这样合并：

```text
K2 的流程顺序
  = 聚类 → 预算有限时长尾采样 → 簇代表图审核 → 叶簇语义去重 → 覆盖复验

Tsubaki.3 的领域经验
  = 领域合适的 embedding → 判断小簇是否视觉连贯 → 长尾补充/重加权

e621 的现有元数据
  = 原始 tag 负责概念归属；Wiki/alias/implication 负责解释和规范化
```

### 最小适配原则

1. **不按 tag 建簇。** 对当前 scope 的图片 embedding 做全局层次聚类；一个 tag 可以跨多个簇，一个簇也可以包含多个 tag。
2. **长尾只在需要缩减总量时启用。** 如果所有合格图片都能保留，可以跳过采样，只做聚类检查和去重。
3. **小簇不能仅凭数量保留。** 先判断视觉是否连贯；水印、边框、重复采集等噪声小簇应被封顶或进入人工审核。
4. **总预算按唯一图片计算。** 一张图片可以同时覆盖多个 e621 tag，但不能把多 tag 计数相加成图片数。
5. **目标 tag 不因频繁而自动压低。** LoRA 的目标概念清单和最低保留量仍需用户确认。
6. **VLM 不替代原始 e621 tag。** 它最多审核簇代表样本、描述视觉模式或标记问题簇。
7. **不照搬 K2 的 caption/Wikipedia/Wikidata 覆盖链。** 你没有 caption，e621 原始 tag 已经提供领域概念映射；直接 tag 和 implication 推断应分开统计。
8. **不要直接照搬 Tsubaki.3 的阈值。** SSCD 的 `0.9/0.92–0.98/0.995` 是 PixAI 报告中的特定 copy-detection 设置，不等于你项目现有 SigLIP 语义去重阈值。

## 一句话判断

Tsubaki.3 和 K2 的共同核心是“用聚类帮助长尾概念获得训练曝光”，但 Tsubaki.3 更强调**领域专用表征、补充数据和重加权**；K2 更强调**通用语义簇、VLM 簇审查、叶簇语义去重和世界知识覆盖复验**。对 e621 LoRA，K2 提供流程骨架，Tsubaki.3 提供动漫域的长尾处理参考，e621 原始 tag 负责概念核对。
